**TL;DR:** omafeed 0.3.1 can mirror a FreshRSS account as well as a Miniflux one: connect your FreshRSS server and omafeed syncs your feeds, folders, articles and read and star state with it, from the window or the command line. It also takes two security fixes in libraries omafeed uses. The library moves to a new schema version, so back it up if you may go back to an earlier omafeed.

## New

- **Mirror a FreshRSS account** ([#65](https://github.com/pch/omafeed/pull/65)). **Sync account…** in the menu, now with a choice of Miniflux or FreshRSS, or `omafeed account connect --service freshrss --username NAME https://your-freshrss`, makes the library follow your FreshRSS server as it does Miniflux: FreshRSS fetches the feeds, and omafeed syncs feeds, folders, articles and read and star state with it whenever it would refresh. omafeed signs in through FreshRSS's Google Reader API with your user name and API password (in FreshRSS, allow API access under Settings → Authentication, then set the password under Settings → Profile → API management), and keeps the password in your keyring. Each sync reads the IDs of every unread and starred article, since FreshRSS cannot say what changed, and downloads only the articles omafeed does not have yet. FreshRSS keeps every feed in a category, so feeds put at the top level go into its default category, which cannot be removed, and removing another category moves its feeds there. A FreshRSS feed's address cannot be changed, so the feed form locks it. Feeds archived in FreshRSS are not offered by its API, so archiving one there removes it from omafeed.

## Security

- **URLs are parsed with url 2.5.9**, which fixes a stack overflow on deeply nested `blob:` URLs ([RUSTSEC-2026-0592](https://rustsec.org/advisories/RUSTSEC-2026-0592), [#65](https://github.com/pch/omafeed/pull/65)).
- **Article HTML is cleaned with ammonia 4.2.5**, which fixes an XSS where embedded SVG or MathML could get past sanitizing ([RUSTSEC-2026-0533](https://rustsec.org/advisories/RUSTSEC-2026-0533), [#60](https://github.com/pch/omafeed/pull/60)).

## Changed

- **Messages name the connected service.** The menu entry is now **Sync account…**, and help and messages say Miniflux or FreshRSS as fits, instead of always Miniflux; `omafeed account status` prints "Connected to Miniflux at …".
- **`OMAFEED_SYNC_TOKEN`** replaces `OMAFEED_MINIFLUX_TOKEN` for giving the API key or password without a keyring; the old name still works.

## Upgrade notes

- **The library moves to schema version 8**, which records which service an account is on and keeps category IDs as text. Earlier omafeed versions refuse to open the library afterwards; back up the data directory first if you may go back. A connected Miniflux account stays connected, with its folders and feeds.

## Requirements

- **Building from source needs Rust 1.95 or newer** (was 1.89), because oo7 0.7, which omafeed uses to keep your API key or password in the system keyring, requires it ([#59](https://github.com/pch/omafeed/pull/59)). The packages and archives are unaffected.
- The `.deb` packages are for Debian 13 or newer and Ubuntu 26.04 or newer. The `.rpm` packages are for Fedora 43 or newer. The Arch package is x86_64; on ARM, build the `PKGBUILD`. The archives need glibc 2.34 or newer, `gtk4`, `libadwaita` 1.6 or newer and `webkitgtk-6.0`.
- FreshRSS sync works with FreshRSS's Google Reader API; it was tested with FreshRSS 1.31. Miniflux sync still needs Miniflux 2.3.2 or newer.
