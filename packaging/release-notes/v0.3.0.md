**TL;DR:** omafeed 0.3.0 can mirror a Miniflux account: connect your Miniflux server and omafeed syncs your feeds, folders, articles and read and star state with it, from the window or the command line. Summary-only feeds can now be read in full inside omafeed, with D. The library moves to a new schema version, so back it up if you may go back to an earlier omafeed.

## New

- **Mirror a Miniflux account** ([#49](https://github.com/pch/omafeed/issues/49), [#50](https://github.com/pch/omafeed/pull/50)–[#54](https://github.com/pch/omafeed/pull/54), [#56](https://github.com/pch/omafeed/pull/56)). **Miniflux account…** in the menu, or `omafeed account connect https://your-miniflux` (with an API key from Miniflux's Settings → API Keys), makes the library follow your Miniflux server: Miniflux fetches the feeds, and omafeed syncs feeds, folders, articles and read and star state with it whenever it would refresh, from the window or `omafeed refresh`, or now with `omafeed sync`. Your feeds Miniflux lacks are subscribed there, and articles you already have keep their read and star state. The same dialog or `omafeed account status` shows the last sync, and disconnecting there or with `omafeed account disconnect` turns everything back into local feeds. The API key is kept in your keyring, or read from `OMAFEED_MINIFLUX_TOKEN`. While connected, adding, editing, moving and removing feeds, and renaming and removing categories, from the window or with `subscribe` and `unsubscribe`, change Miniflux first, and importing OPML subscribes Miniflux to the new feeds, each in the category named like its folder. Syncs after the first one download only what changed, so they stay quick however many articles are unread. A feed Miniflux refuses stays in omafeed with the reason, and is offered to Miniflux again when you fix its address, import it again, press refresh, or run `omafeed sync`. Needs Miniflux 2.3.2 or newer.

- **Read the full article from summary-only feeds** ([#55](https://github.com/pch/omafeed/pull/55)). Press D, or the download button above the article, to fetch the article's web page and read its main text in omafeed; it is kept for reading offline, and D again shows the feed's version. `omafeed article 42 --full` does the same from the command line. While a Miniflux account is connected, Miniflux fetches it, with your scraper rules for the feed.

## Upgrade notes

- **The library moves to schema version 7**, which records what each feed, folder and article is on a Miniflux server, where the next sync continues, and full articles fetched from their web pages. Earlier omafeed versions refuse to open the library afterwards; back up the data directory first if you may go back.
- **`omafeed --help` lists two more commands**, `sync` and `account`. Other output is unchanged, including `refresh --json`, which keeps its shape while an account is connected.

## Requirements

- **Building from source needs Rust 1.89 or newer** (was 1.88), because rusqlite 0.41, which omafeed uses to keep your library in SQLite, requires it ([#48](https://github.com/pch/omafeed/pull/48)). The packages and archives are unaffected.
- The `.deb` packages are for Debian 13 or newer and Ubuntu 26.04 or newer. The `.rpm` packages are for Fedora 43 or newer. The Arch package is x86_64; on ARM, build the `PKGBUILD`. The archives need glibc 2.34 or newer, `gtk4`, `libadwaita` 1.6 or newer and `webkitgtk-6.0`.
