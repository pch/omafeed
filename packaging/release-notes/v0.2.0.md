**TL;DR:** Omafeed 0.2.0 adds a command line for scripts and LLM agents, and a search that forgives typos and plurals and finds words as you type. An open window now shows changes made from the command line within a couple of seconds. The library moves to schema version 3, so back it up if you may need to go back to 0.1.x.

**Download:** [Arch Linux recipe](https://github.com/pch/omafeed/releases/download/v0.2.0/PKGBUILD) (`makepkg -si`) · Linux archive ([x86_64](https://github.com/pch/omafeed/releases/download/v0.2.0/omafeed-0.2.0-x86_64-linux.tar.gz))

## New

- **A command line for scripts and LLM agents** ([#5](https://github.com/pch/omafeed/pull/5)). `omafeed feeds`, `articles`, `search`, `article`, `read`, `unread`, `star`, `unstar`, `subscribe` and `unsubscribe` work with the same library as the app. Output is plain text by default and one line of JSON with `--json`, which also works on `refresh` and `discover`. `articles --since 24h` reads as many pages as needed, so a daily digest is not limited to the newest 200 articles. Read, unread and star commands name each article they change, and a batch with a wrong ID changes nothing. `unsubscribe` deletes a feed and all its articles, starred ones included, so it needs `--yes`. `omafeed --help` now starts with the version, and the README documents every command.
- **Forgiving search** ([#6](https://github.com/pch/omafeed/pull/6)). Search in the app and the command line now corrects typos (`agentc` finds `agentic`), treats plural and singular alike, and matches the start of the last word so results appear as you type. A word that appears in your articles is never swapped for a similar one, and words under five letters and numbers are matched exactly. Use `--exact` on the command line to switch it off. Nothing in the library file changes for this. "Mark current view read" follows the same search.

## Improved

- **Changes from the command line show in an open window.** The window checks for writes by other programs every two seconds and reloads. Before, `omafeed star 2` was saved but not shown until you switched views or restarted.
- **Plain and readable article text keeps its structure.** `omafeed article` keeps blank lines between paragraphs, headings, lists, quotes and fenced code, keeps line breaks inside `<pre>`, and numbers lists from their start value. Words are separated where a block ends as well as where it starts, so a summary followed by text no longer reads as one word, in the text or in the search index.

## Fixed

- **Searches no longer match unrelated words through plurals.** `notes` no longer matched `not`, `news` matched `new` or `times` matched `tim`, and marking such a search read no longer marked those articles. Accents typed as combining marks now get typo correction too, and a stray NUL character in a query no longer fails the search.
- **Reading and starring in the window is no longer undone by a reload.** When another program had changed the library, a reload that raced with a star or read change in the window could show the old state.
- **The command line behaves in pipes and over long lists.** `omafeed articles | head -1` stops quietly instead of panicking, every page of a long list comes from one snapshot so the app writing meanwhile cannot repeat or skip articles, dates print in local time, `--limit 0` is rejected, and database errors from `article` are reported instead of "No article with id N".

## Upgrade notes

- **The library moves to schema version 3,** which re-reads stored articles to refresh previews and search text. It is upgraded the first time 0.2.0 opens it. Older versions then refuse it with "Database was created by a newer Omafeed version", so back up the data directory (`~/.local/share/omafeed`) first if you may need to go back.

## Requirements

Omafeed needs `gtk4`, `libadwaita` 1.6 or newer and `webkitgtk-6.0`. The x86_64 archive is built on Arch Linux. The command line needs the GTK libraries but no display, so it also runs over SSH.
